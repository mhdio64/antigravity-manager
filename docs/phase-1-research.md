# بررسی منابع انتشار و محیط‌های هدف

## منبع دانلود App و IDE

**به‌روزرسانی پس از بررسی کد صفحهٔ گوگل:** [صفحهٔ انتشارها](https://antigravity.google/releases) برای هر محصول یک فید JSON مستقل می‌خواند. [فید App](https://antigravity-hub-auto-updater-974169037036.us-central1.run.app/releases) و [فید IDE](https://antigravity-ide-auto-updater-974169037036.us-central1.run.app/releases) آرایه‌ای از نسخه و شناسهٔ انتشار دارند. نمونهٔ اولیه از همین فیدها و الگوی لینک خود صفحه استفاده می‌کند. این فیدها قرارداد عمومی پایداری ندارند و در صورت شکست، صفحهٔ رسمی مسیر جایگزین است.

[صفحهٔ رسمی دانلود گوگل](https://antigravity.google/download) در بررسی ۱۳ نوامبر ۲۰۲۶ دو بخش مستقل با لینک مستقیم Linux x64 داشت. App نسخهٔ 2.31.2 روی `storage.googleapis.com` و IDE نسخهٔ 2.7.0 روی `edgedl.me.gvt1.com` عرضه شده بود. این شماره‌ها نمونهٔ زمان بررسی‌اند. [صفحهٔ انتشارها](https://antigravity.google/releases) نسخه‌های قبلی را فهرست می‌کند و [راهنمای رسمی](https://antigravity.google/docs/getting-started) به‌روزرسانی IDE از طریق APT یا دریافت دوبارهٔ tarball را توضیح می‌دهد.

صفحهٔ رسمی دانلود مرجع مقایسهٔ نتیجهٔ فیدهاست. نسخه و لینک Linux x64 هر محصول باید با بخش همان محصول مقایسه شوند. پاسخ غایب یا نامعتبر باید به وضعیت «بررسی ناموفق» برسد. کاربر همچنان بتواند نصب موجود را اجرا کند و صفحهٔ رسمی را باز کند. صفحهٔ تاریخچه و شماره‌های قدیمی نباید جایگزین نتیجهٔ بررسی موفق شوند.

پیش از فعال‌کردن نصب خودکار، اعتبارسنجی آرشیو و مقصد دانلود، وجود یا نبود checksum رسمی و امکان ادامهٔ دانلود باید برای هر دو فایل جداگانه بررسی شوند. در این مرحله فایل‌های اجرایی دریافت یا اجرا نشده‌اند و API پایدار اثبات نشده است.

## Qt و بستهٔ deb

| محیط پیشنهادی amd64 | پایهٔ بسته و نسخهٔ مشاهده‌شدهٔ Qt Declarative | وضعیت |
| --- | --- | --- |
| Kubuntu 26.04 / KDE | Resolute، `6.10.2+dfsg-3` | هدف اصلی، تست عملی در انتظار |
| Ubuntu 26.04 / GNOME | Resolute، `6.10.2+dfsg-3` | هدف پیشنهادی، تست عملی در انتظار |
| Ubuntu 24.04 / GNOME | Noble، `6.4.2+dfsg-4build3` | هدف پیشنهادی برای بررسی پایهٔ قدیمی‌تر |
| Linux Mint 22 / Cinnamon | پایهٔ Ubuntu 24.04، نسخهٔ واقعی بسته روی VM باید ثبت شود | هدف پیشنهادی، تست عملی در انتظار |

منابع: [بستهٔ Resolute](https://packages.ubuntu.com/resolute/qt6-declarative-dev)، [بستهٔ Noble](https://packages.ubuntu.com/da/noble/qt6-declarative-dev)، [پایهٔ Mint 22](https://www.linuxmint.com/rel_wilma_whatsnew.php).

پیشنهاد اولیه Qt Quick/QML و C++ با حداقل API نسخهٔ 6.4.2 است تا Noble از ابتدا قابل ارزیابی بماند. نخستین بسته را روی Noble با وابستگی‌های سیستمی بسازیم و همان فایل deb را روی همهٔ محیط‌ها نصب کنیم. نتیجهٔ تست تعیین می‌کند یک خروجی مشترک کافی است یا برای پایه‌های توزیع بسته‌های جدا لازم‌اند. در نمونهٔ اولیه، وابستگی‌های QML Controls، Layouts، Qt Network و نمایش روی Wayland و X11 را روی سیستم تمیز بررسی و نسخه‌های حل‌شده را ثبت کنیم.

## ماتریس پذیرش انتشار

برای هر محیط جدول، موارد زیر برای App و IDE مستقل ثبت شوند. نتیجهٔ فعلی همهٔ ردیف‌ها «در انتظار اجرا» است.

| آزمون | نتیجهٔ مورد انتظار |
| --- | --- |
| نصب deb و اجرای مدیر | نصب گرافیکی با وابستگی‌های کامل و اجرای مدیر از منو |
| نصب تازه و شناسایی نصب قبلی | نصب کاربری، آیکن و اجرای صحیح از منو، انتقال فقط با تأیید و حفظ تنظیمات |
| آپدیت با برنامهٔ باز و دانلود قطع‌شده | ادامهٔ دانلود در صورت پشتیبانی و انتظار برای بسته‌شدن محصول |
| خرابی آرشیو، کمبود فضا، قطع عملیات | نسخهٔ فعال سالم و قابل اجرا بماند |
| شکست بررسی نسخه | خطای روشن، امکان بررسی مجدد و اجرای نسخهٔ نصب‌شده |
| RTL، شکست RTL و بازگردانی | فقط روی نسخهٔ تأییدشده، امکان حذف تغییر RTL و برگشت به نسخهٔ قبلی |
| حذف برنامه | حفظ تنظیمات به‌صورت پیش‌فرض و حفظ پروژه‌ها |
| فارسی، انگلیسی، صفحه‌کلید و گزارش | جهت درست رابط، عملیات قابل دسترس با صفحه‌کلید و خروجی گزارش بدون دادهٔ حساس |

نمونهٔ بررسی فیدها در [prototype](../prototype/README.md) قرار دارد. پذیرش کامل به تشخیص مستقل هر دو لینک Linux x64 و اجرای بسته روی Kubuntu 26.04 و پایهٔ Noble وابسته است.
